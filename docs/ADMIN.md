# Админка меню — инструкция

## 0. Что нового в v17 (октябрь 2026)

**Один раз после обновления сайта** откройте Supabase → SQL Editor и выполните файл
`supabase/2026_10_dish_pages_and_design.sql`. Он добавляет новые поля блюда и отвязывает
старые фото, которые раньше лежали внутри сайта (`/dish-photos/...`). Файл можно запускать
повторно — ничего не сломается. Пока он не выполнен, новые поля в админке не сохранятся
(будет ошибка при сохранении).

- **Фото больше не лежат в архиве сайта.** Каждое фото загружается из админки
  (Блюда → открыть блюдо → Фото). Блюдо без фото выглядит аккуратно: строка меню без картинки,
  а на странице блюда — эмблема LOOK.
- **Страница блюда.** Нажатие на блюдо открывает его страницу (адрес вида `/dish/…`, им можно
  поделиться): фото, цена, вес, время приготовления, описание, состав, аллергены, КБЖУ,
  соседние блюда раздела и кнопки «предыдущее / следующее».
- **Кнопка «+» вместо сердечка** — добавляет блюдо в «Мой список», затем превращается в «− 1 +».
  Список живёт на телефоне гостя 12 часов, блюда из стоп-листа и удалённые блюда из него убираются сами.
- **Время приготовления** — в меню, на странице блюда, фильтр «Быстро, до 15 мин» и в списке
  гостя («Будет готово примерно через N мин» — по самому долгому блюду, кухня готовит параллельно).
- **Раздел «Дизайн» в админке** — темы, свои цвета, логотип (подробно — раздел 16).
- Если база не отвечает, гость видит последнюю версию меню, сохранённую на его телефоне,
  и предупреждение, что цены и наличие могут отличаться.

## 1. Как всё устроено

```
Вы → админка (/admin) → Supabase (данные + фото) → сайт на Vercel → гость с телефона
```

| Название | Что это для вас |
|---|---|
| **Vercel** | Здесь живёт сайт меню. Заходите один раз — вписать два ключа. |
| **Supabase** | База: категории, блюда, загруженные фото. Настроить и забыть. |
| **Админка** | Страница `/admin` на вашем сайте. Здесь вы работаете каждый день. |

Меню не ломается, если база недоступна: гость видит встроенное меню «Sala» из кода.
Пустой страницы никто не увидит.

**Через админку меняется:** категории (название, иконка, порядок, показать/скрыть),
блюда (название, описание, цена, гранаж, фото, отметка «Рекомендовано», показать/скрыть,
порядок внутри категории).

**Не меняется отсюда:** остальные меню заведения (Bar, Matcha, Mic Dejun, Asia) — они видны
гостю в правой боковой панели («Meniuri și setări» → значок ☰ в шапке сайта) со статусом
«În curând» и ссылкой на официальный сайт lookrestobar.md, но их блюда пока нигде не заведены
в базе. Когда пришлёте содержимое любого из них, его можно оцифровать так же, как «Sala» —
напишите нам, это отдельная небольшая доработка (по одной категории/блюду это не сделать
через админку, список меню сейчас зашит в код сайта).

## 2. Разовая настройка: база

1. **Проект в Supabase.** [supabase.com](https://supabase.com) → New project.
   Регион `Central EU (Frankfurt)`. Пароль базы сохранить сразу — второй раз не покажут.
2. **Таблицы.** SQL Editor → New query → вставить весь `supabase/schema.sql` → Run.
   Ожидаемый ответ: `Success. No rows returned`. Безопасно запускать повторно в любой
   момент (например, после обновления проекта) — он только добавляет то, чего не хватает,
   и ничего не удаляет.
3. **Меню «Sala».** Для **новой, пустой** базы: New query → весь `supabase/seed.sql` → Run.
   Загружает 10 категорий и 60 блюд — выверено по официальному PDF заведения (август 2026),
   с переводами RU/EN и настоящими фото блюд. Повторный запуск дубликатов не создаёт.

   > **Если база уже была заполнена** (сайт уже работает, категории и блюда уже есть) —
   > `seed.sql` в этом случае ничего не тронет, его защита от дублей и рассчитана на пустую
   > базу. Чтобы обновить уже работающий сайт до этой версии меню (новые переводы, фото из
   > PDF, эмодзи у категорий), выполните вместо этого `supabase/menu_refresh_2026.sql`.
   > **Важно:** этот скрипт удаляет ВСЕ текущие категории и блюда и заводит их заново —
   > любые бейджи, гранаж или фото, которые вы вручную поменяли в админке для старых
   > записей, не перенесутся (сами фото файлы в Storage не удаляются, но у большинства
   > новых блюд уже прописано фото из PDF, так что переливать их заново не нужно).
   > Перед запуском стоит на всякий случай посмотреть текущие `menu_items` в Table Editor.
4. **Логин.** Authentication → Users → Add user → Create new user.
   Обязательно включить **Auto Confirm User**.
5. **Права.** SQL Editor:
   ```sql
   select public.grant_admin('вашапочта@example.com');
   ```
   Ответ: `Gata: … este acum administrator.`

**Проверка:** таблицы `menu_categories` (10 строк) и `menu_items` (60 строк) в Table Editor,
ваша почта в Users с датой подтверждения, одна строка в `admin_users`.

### Чтобы база не «засыпала»

На бесплатном тарифе Supabase ставит проект на паузу, если к нему **семь дней подряд**
не было ни одного запроса — это не проблема, если QR-код на столах сканируют регулярно
(каждый заход гостя — это запрос к базе). Если заведение закрывается на сезон дольше недели,
просто откройте Supabase Dashboard и нажмите «Restore» перед открытием.

**Или не полагаться на удачу вовсе.** В проекте есть готовый файл
`.github/workflows/supabase-keepalive.yml` — он раз в день сам стучится в базу одним лёгким
запросом (тем же, что и обычный гость), чтобы счётчик «семь дней без запросов» никогда не
доходил до нуля, даже если заведение закрыто и QR-код никто не сканирует. Настройка один раз:

1. Репозиторий на GitHub → **Settings → Secrets and variables → Actions → New repository secret**
2. Добавить два секрета с теми же значениями, что уже стоят в Vercel (раздел 3 выше):
   - `SUPABASE_URL` = то же, что `VITE_SUPABASE_URL`
   - `SUPABASE_ANON_KEY` = то же, что `VITE_SUPABASE_ANON_KEY`
3. Готово — расписание уже прописано в файле, ничего запускать вручную не нужно.

Проверить, что сработало: вкладка **Actions** в репозитории на GitHub → workflow
«Supabase keep-alive» → там же можно нажать **Run workflow**, чтобы прогнать его прямо сейчас
и убедиться, что он не падает с ошибкой (значит, секреты вписаны верно).

> Это тот же самый `anon` ключ, что уже открыт браузеру гостя на самом сайте — он даёт только
> право на чтение, разрешённое RLS-политикой, ничего опаснее. `service_role` сюда вписывать
> не нужно и нельзя.

## 3. Разовая настройка: сайт

Supabase → Project Settings → API. Нужны **Project URL** и **anon public**.

> Ключ `service_role` лежит рядом и даёт полный доступ в обход всех ограничений.
> Его нельзя вставлять в настройки сайта, в переписку и на скриншоты.

Vercel → Settings → Environment Variables:

```
VITE_SUPABASE_URL      = https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY = eyJhbGci...
```

Отметить Production + Preview + Development, сохранить, затем
**Deployments → ⋯ → Redeploy**. Без пересборки старый сайт ключей не увидит.

### Автообновление с GitHub

Если проект на Vercel был создан через **Import Git Repository** (так и есть у этого
проекта), Vercel сам следит за GitHub-репозиторием — отдельно ничего «включать» не нужно:

- каждый `push` в основную ветку (`main`) автоматически пересобирает и публикует **Production**
  — тот самый сайт, который видят гости, через 1–2 минуты после пуша;
- любая другая ветка или Pull Request получает свою отдельную **Preview**-ссылку — можно
  проверить изменения, не трогая живой сайт.

Проверить это можно в Vercel → проект → **Settings → Git**: там будет привязанный репозиторий
и ветка Production. Отключить автодеплой (если вдруг понадобится ручной контроль) — там же,
переключателем **Ignored Build Step** или ослаблением прав интеграции в GitHub → Settings →
Integrations → Vercel. По умолчанию трогать это не нужно — автообновление и есть весь смысл
такой связки.

## 5. Категории

Раздел **Категории**: квадратный превью-блок и рядом поле **эмодзи** — именно этот эмодзи
показывается на сайте перед названием категории (в табах, в заголовке секции, как заглушка
вместо фото у блюда без фотографии). Впишите туда любой эмодзи с клавиатуры телефона/компьютера
(🥗, 🐟, 🍔…) — превью обновится сразу. Если поле пустое, превью показывает блёклую
вилку-нож — это заглушка, а не «выбранный» эмодзи, поэтому на вид не спутать с настоящим.
Дальше — название, порядок (тянуть за точки слева или стрелками), показать/скрыть иконкой
глаза, удалить корзиной.

> На базе, которая уже была живой до этой функции, поле эмодзи у старых категорий пустое —
> у всех сразу будет одна и та же заглушка, пока не впишете эмодзи. Для десяти стандартных
> категорий это можно сделать одной командой: `supabase/emoji_backfill.sql` в Supabase →
> SQL Editor. Для своих категорий — просто впишите эмодзи в поле вручную, один раз.

Кнопка **Категория новая** внизу заводит пустую категорию, страница сама прокручивается
к ней и на секунду подсвечивает золотым — переименуйте её сразу.

> Удаление категории не удаляет блюда в ней — они просто перестают показываться на меню,
> пока их не перенесёте в другую категорию (в редакторе блюда). Такие «осиротевшие» блюда
> не теряются: они появляются в разделе **Preparate** отдельной жёлтой панелью «Без категории»
> сверху страницы — оттуда откройте каждое и выберите категорию заново.

## 6. Блюда

Раздел **Preparate** — список блюд, сгруппированный по категориям. Кнопка **Adaugă** у
каждой категории заводит новое блюдо прямо в ней и открывает редактор.

> Если наверху страницы видна жёлтая панель **«Без категории»** — это блюда, у которых
> удалили категорию (см. раздел 5). На сайте они не показываются. Откройте блюдо и выберите
> для него категорию в редакторе — панель для него исчезнет.

В редакторе одного блюда:

| Поле | Что вписать |
|---|---|
| Фото | Перетащить в рамку. Хранится в Supabase Storage, сжимается автоматически до разумного размера |
| Categorie | В какой категории показывать блюдо |
| Denumire | Название, как в меню |
| Descriere | Состав/ингредиенты — короткой строкой |
| Preț | Число, в леях |
| Gramaj | Необязательно, например «300 g» |
| Vizibil pe meniu | Снимите галочку, чтобы временно убрать блюдо с сайта, не удаляя его |

«Рекомендуем» — это больше не отдельная галочка, а один из вариантов в разделе
**Etichetă pe meniu** ниже (раздел 8) — та же плашка, что и «Новинка»/«Скидка»/«Стоп-лист»,
просто ещё один цвет. Раньше это были два разных места с одинаковым результатом; теперь
только одно.

**Каждое поле сохраняется само**, как только вы кликнете мимо него (или сразу — для фото
и переключателей). Отдельной кнопки «Сохранить» нет и не нужна.

**Порядок блюд внутри категории** — стрелками вверх/вниз в списке Preparate, либо мышкой:
возьмите карточку за значок из шести точек в левом верхнем углу фото и перетащите на нужное
место. Стрелки при этом никуда не делись — на телефоне (там перетаскивание мышкой не работает)
или с клавиатуры пользуйтесь ими.

**Удалить** — красная корзина, с подтверждением. Удаляет и фото из хранилища. Если нужно
просто временно убрать блюдо — снимите галочку «Vizibil pe meniu» вместо удаления.

## 7. Языки — панель и сайт

Раздел **Setări** в админке (пункт меню слева) переключает язык **самой панели** —
меню, кнопки, подписи полей — между румынским, русским и английским. Выбор запоминается
только в этом браузере и не влияет на то, что видят гости.

**Язык сайта** гость выбирает сам — переключатель RO / RU / EN стоит в правом верхнем углу
меню, рядом с переключателем темы. Работает независимо от языка админки.

Чтобы блюдо или категория показывались переведёнными, откройте её в редакторе:

- **Категории** — у каждой категории есть кнопка-стрелка «Traduce»/перевод, которая
  раскрывает поля «Denumire (RU)» и «Denumire (EN)» под строкой категории.
- **Preparate** — в редакторе блюда над полями «Denumire»/«Descriere» есть вкладки
  **RO / RU / EN**. Вкладка RO — это основные поля (как раньше), RU и EN — перевод названия
  и описания, показываются гостю, когда он переключает язык сайта.

Если перевод не заполнен, гость всё равно увидит текст — только на румынском (базовый
язык) вместо выбранного, так меню никогда не показывает пустое поле.

## 8. Бейджи на карточках блюд

В редакторе блюда, ниже переключателя «Vizibil pe meniu», есть раздел **Etichetă pe meniu**
с пятью вариантами, каждый — своя иконка и цвет, точь-в-точь как плашка будет выглядеть на
самой карточке блюда: без плашки, **Recomandat** (золотая, звезда), **Nou** (голубая, искра),
**Reducere** (коралловая, значок процента — если вписать число в поле «% скидки», на плашке
покажется «-20%» вместо слова «Reducere»), **Stoc epuizat** (приглушённая тёмная, значок
запрета — дополнительно гасит фото и блокирует кнопку добавления в список у гостя).

Для **Reducere** цена на карточке блюда автоматически показывается парой: старая цена
зачёркнута, рядом — новая, уже посчитанная по проценту скидки (гостю не нужно ничего
считать в уме). Сумма в списке для официанта и итог тоже считаются уже по цене со скидкой.
Меняется только сам факт скидки и процент — цену в поле «Preț» менять не нужно, это
исходная (полная) цена.

Ниже — **срок действия плашки**: без срока, 1 час, 1 день, 1 неделя, 1 месяц, или своя дата
и время. Как только срок истекает, плашка сама пропадает с меню — заходить и убирать её
вручную не нужно. Изменить срок или снять плашку можно в любой момент тем же способом.

## 9. Поиск, шапка и боковая панель на сайте

Значок-лупа в шапке сайта открывает поиск по всему меню (название, состав, категория) сразу
на трёх языках, с учётом румынских диакритик (гость может набрать «peste» вместо «pește» —
найдёт всё равно). Окно поиска теперь занимает весь экран (раньше это была короткая шторка
сверху, и на длинных страницах под ней было видно потускневшее меню — выглядело как баг;
теперь такого нет). Результаты показываются точно такими же карточками, как в самом меню
(фото, вес, плашка, кнопка ♡) — не просто строчкой текста, — и клик по карточке прокручивает
прямо к блюду в общем списке, на секунду подсвечивая его. Можно ввести несколько слов в любом
порядке («pui salata» или «salata pui» — без разницы), а для русского языка поиск дополнительно
понимает основные словоформы: «курица» находит и «куриный», и «куриное», и «курицей» —
не только точное совпадение. Результаты сортируются по приоритету: сначала блюда, у которых
совпадение есть прямо в названии, потом — у которых совпадение только в составе, и в самом
конце — те, что нашлись лишь по названию категории. Например, по запросу «somon» сначала
покажутся блюда с лососем в названии («Тартар из лосося», «Салат с лососем»), а уже после них —
блюда, где лосось просто упомянут в составе. Отдельно настраивать нечего — работает по данным,
которые уже есть в категориях и блюдах.

Значок-«☰» рядом с лупой открывает боковую панель справа: список всех меню заведения (Sala —
активно, остальные четыре — «În curând» со ссылкой на официальный сайт), категории текущего
меню для быстрого перехода, и в самом низу — настройки (язык сайта, тема день/ночь). Раньше
настройки были отдельным всплывающим окошком — теперь всё в одном месте.

При скролле вниз шапка с логотипом уезжает вверх, а таб с категориями остаётся закреплён
у самого верха экрана — так гость всегда видит, по какой категории листает, а место
для меню освобождается. При скролле вверх шапка возвращается. Это тоже часть дизайна
сайта, в админке ничего не переключается.

Таб текущей категории в этой полоске подсвечивается сам — по мере того, как гость
пролистывает меню, подсветка переключается на категорию, которая сейчас на экране, и
сама полоска прокручивается по горизонтали, чтобы подсвеченный таб был виден (если
категорий много и они не помещаются на экране). Клик по любому табу по‑прежнему
прокручивает прямо к этой категории, и подсветка сразу переходит на неё, не дожидаясь
скролла. Настраивать здесь тоже нечего — работает автоматически по списку категорий.

Карточки блюд теперь плавно проявляются («всплывают» снизу с лёгким увеличением), когда
гость до них долистывает, а
заголовок на главном экране и разделитель под ним аккуратно появляются по очереди при
открытии сайта — вместо того чтобы просто резко показаться целиком. Если на экране
сразу несколько карточек в ряд (широкий экран), они проявляются не одновременно, а
волной слева направо. Заголовок каждой категории (эмодзи + название + линия) тоже
проявляется по-своему при долистывании: эмодзи выскакивает с лёгкой пружинкой, а линия
под названием как бы «дорисовывается» слева направо. У гостей с настройкой «уменьшить
анимации» в телефоне/браузере всё это, как и раньше, показывается сразу, без движения.
Настраивать здесь тоже нечего.

Список для официанта (кнопка со списком выбранных блюд снизу) теперь показывает у
каждой позиции маленькое фото и состав блюда, а не только название и цену — официанту
проще сверить заказ, не листая обратно в меню.

Фото блюда в карточке (и в результатах поиска) теперь можно тапнуть — оно открывается
крупно на весь экран поверх меню, с тёмной подложкой и названием блюда внизу. Закрыть
можно крестиком в углу, тапом по самому фото или клавишей Esc (на компьютере). Если у
блюда фото не загружено, вместо него по‑прежнему просто эмодзи категории — тапать
там не на что, и курсор это не показывает. Настраивать здесь нечего: если у блюда есть
фото (см. §6), увеличение работает само.

Кнопки лупы и «☰» в шапке (а заодно и все остальные кнопки на сайте) теперь реагируют на
тап без короткой заминки, которая раньше иногда была заметна на телефоне — особенно в
браузере, встроенном в Instagram/TikTok, где такая задержка перед нажатием случается чаще
всего. Заодно открытие поиска и бокового меню больше не пересчитывает и не перерисовывает
всю сетку блюд на странице (а раньше пересчитывало, хоть это никак не было видно — просто
съедало те самые лишние миллисекунды перед тем, как панель начинала выезжать), так что
открытие ощущается мгновенным даже на большом меню и слабом телефоне. Настраивать здесь
нечего — это техническая правка под капотом, снаружи меняется только скорость реакции.

## 10. Юридические страницы и подвал сайта

В самом низу сайта — футер в три колонки на широком экране (логотип и название, адрес и
телефон со значками, кружки-иконки соцсетей), а ниже, под тонкой разделительной линией —
четыре ссылки (**Termeni și condiții**, **Politica de confidențialitate**, **GDPR**,
**Politica de cookie-uri**) и подпись «Realizat cu 🍪 de cookiekiller.online» со ссылкой. На
телефоне всё то же самое, просто одной колонкой по центру. Тексты этих четырёх страниц
написаны с учётом того, как реально работает сайт (никакой аналитики, только
язык/тема/список в localStorage телефона) и лежат в `src/pages/legal/content.js` — если
что-то в них нужно поправить (адрес, телефон, формулировку), редактируется там, отдельно на
трёх языках. Сами контакты (адрес, телефон, ссылки на Instagram/Facebook/TikTok) берутся из
`src/data/contact.js` — один файл на весь сайт, включая футер.

Логотип в футере — присланные вами два SVG-файла: широкий горизонтальный
(`src/assets/logo-horizontal.svg`, тот же, что и в шапке сайта, включая шапку юридических
страниц) показывается на широком экране, а вертикальный (`src/assets/logo-vertical.svg`) —
на телефоне, где для широкой версии просто не хватает места по ширине. Переключение между
ними чисто по CSS (по ширине экрана), без единой строчки JS — так что подмена не мигает и не
прыгает при загрузке. Заменить сам файл логотипа (например, если дизайн поменяется) можно,
просто положив новый SVG с тем же именем в `src/assets/`.

### Всё это — теперь редактируется прямо из админки

Контакты, текст в подвале и все четыре юридические страницы больше не зашиты в код — в
боковом меню админки появился новый раздел **«Conținut»** (значок с листом бумаги), а в нём
шесть вкладок:

- **Contacte** — адрес, ссылка на Google Maps, телефон (отдельно отображаемый текст и
  `tel:`-ссылка), ссылки на Instagram/Facebook/TikTok и ссылка на официальный сайт (та, что
  показывается в кнопке «Vezi pe site-ul oficial» для меню со статусом «În curând»).
- **Subsol** — короткая фраза под логотипом в подвале, отдельно на трёх языках.
- **Termeni / Confidențialitate / GDPR / Cookie-uri** — заголовок страницы и сами разделы
  (заголовок + абзац) на каждом из трёх языков; разделы можно добавлять, удалять и менять
  местами стрелками. Дата «Actualizat: …» под заголовком страницы теперь не текст, который
  надо руками поддерживать в актуальном состоянии, — она проставляется автоматически, в
  момент, когда вы сохраняете правку на этой странице.

Как и с блюдами, каждое поле сохраняется само, как только вы кликаете мимо него — отдельной
кнопки «Сохранить» нет. Пока раздел ни разу не редактировался, сайт показывает встроенный
текст (тот самый, что был в коде до этого) — гость никогда не увидит пустую страницу.

Чтобы это заработало на уже развёрнутой базе, нужно один раз выполнить актуальный
`supabase/schema.sql` в Supabase → SQL Editor (он добавляет таблицу `site_content` — см.
раздел 2; повторный запуск всего файла безопасен и ничего не ломает в уже существующих
таблицах).

## 11. Место в Supabase (Обзор)

В разделе **Обзор** — виджет **«Loc în Supabase»**: сколько места занято из бесплатного
тарифа (Fișiere — бакет с фото, Bază de date — сама база), в реальном времени, теми же
числами, что показывает сама панель Supabase в Project Settings → Usage. Полоска желтеет
после 70% и краснеет после 90% — сигнал, что пора либо чистить старые фото, либо переходить
на платный тариф. Если виджет не грузится с ошибкой прав — значит на базе ещё не выполнен
обновлённый `supabase/schema.sql` (в нём добавлена функция `admin_usage_stats`, см. раздел 2).

## 12. Какие фото готовить

| Размер | Формат и вес |
|---|---|
| Любое, желательно горизонтальное или квадратное (карточка обрезает под 4:3) | JPG/WEBP до 5 МБ — панель сама уменьшает до 1600px по длинной стороне |

Правило важнее цифр: **WEBP или JPG вместо PNG** для фотографий — весит в разы меньше при
той же чёткости.

## 13. Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| «Nu aveți drepturi» | Выполнить `grant_admin` со своей почтой, обновить страницу |
| «Acest identificator (slug) este deja folosit» | Такое бывает только у категорий — на слаг это не влияет для блюд |
| «Sesiunea a expirat» | Обновить страницу, войти заново |
| «Nu există conexiune cu serverul» | Проверить интернет, затем [status.supabase.com](https://status.supabase.com) |
| На сайте старое встроенное меню вместо базы | Сайт не достучался до базы: проверить ключи в Vercel и Redeploy |
| Вместо фото — иконка категории | Так и задумано без фото. Если фото загружено, но не показывается — пересохраните его в JPG |

## 14. Чего делать нельзя

- **Показывать кому-либо ключ `service_role`.** Полный доступ в обход всех ограничений.
- **Удалять таблицы в Table Editor.** Удалённая `menu_items` — это все блюда сразу.
- **Выключать Row Level Security.** Это то правило, из-за которого гость может читать меню,
  но не может ничего в нём поменять.

## 15. Словарик

| Слово | Что значит |
|---|---|
| Deploy / Redeploy | Пересобрать и опубликовать сайт заново |
| Slug | Техническое имя категории в базе — не показывается гостям |
| RLS | Правила базы: читать — все, менять — только вы |
| Storage | Место в Supabase, где физически лежат загруженные фото |
| anon key | Публичный ключ, только чтение опубликованного. Ему и положено быть в браузере |
| service_role key | Секретный ключ с полным доступом. Не для вас и не для сайта |

## 16. Страница блюда и «Дизайн» (v17)

### Поля страницы блюда (Блюда → открыть блюдо → «Страница блюда»)

| Поле | Что делать | Что увидит гость, если пусто |
|---|---|---|
| Состав | Через запятую. На вкладках RU/EN — перевод. | Состав берётся из описания (в нашем меню описание и есть состав) |
| Время приготовления | Кнопки 5–60 мин или своё число | Время не показывается, блюдо не попадает в фильтр «Быстро» |
| Аллергены | Отметить из списка 14 аллергенов ЕС. «Без основных аллергенов» — если проверили и их нет | «Аллергены не указаны, уточните у официанта». При фильтре по аллергенам такие блюда скрываются |
| КБЖУ на порцию | Калории, белки, жиры, углеводы. Дробные — через точку или запятую | Блок не показывается. Если калории пусты, а Б/Ж/У заполнены — сайт посчитает сам и пометит «*» |

Важно: аллергены и КБЖУ заполняет кухня. Сайт ничего не придумывает — пустое поле честно
показывается как «не указано».

### Дизайн → Темы

- **Готовые темы:** Terasa (по умолчанию), Noir, Bordeaux, Cobalt, Contrast. У каждой есть ночной и дневной вариант.
- Нажмите на тему — она загрузится в редактор. Справа — живой предпросмотр.
- **Цвета:** 10 цветов отдельно для ночного и дневного режима, скругление углов и режим, который гость видит первым.
  Если какое-то сочетание плохо читается, под цветами появится предупреждение с цифрой контраста.
- **«Опубликовать на сайте»** — только эта кнопка меняет сайт. До неё можно пробовать что угодно.
- **«Сохранить как свою тему»** — тема попадает в «Мои темы», сайт при этом не меняется.
  Удаление своей темы тоже не меняет сайт.
- Гость по-прежнему может переключить день/ночь в меню (☰ → Тема).

### Дизайн → Логотип

- SVG, PNG или JPG. Показывается в шапке и подвале на всех страницах сайта.
- **Логотип для дневного режима** — необязательный, если основной светлый и теряется на светлом фоне.
- **Высота в шапке** — ползунок 20–72 px.
- «Вернуть стандартный» — снова логотип LOOK. Старые файлы логотипов удаляются из хранилища сами.
